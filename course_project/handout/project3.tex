\section{Purpose and learning objectives}

Standard retrieval-augmented generation stores document chunks and asks a
language model to repeatedly reason over retrieved text. \PANINI instead
converts documents into GSWs: heterogeneous semantic networks containing
entities, verb-phrase/event nodes, roles, states, and grounded question--answer
(QA) edges. At inference time, \RICR decomposes a multi-hop query and searches
for compact chains of QA pairs through this structured memory.

This project connects the \PANINI framework to core topics from ECE 232E:
heterogeneous graph construction, network projection, connectivity,
centrality, ranking, sparse and dense search, beam search, scaling, and
controlled experimental evaluation. By the end of the project, you should be
able to:

\begin{enumerate}
  \item construct and characterize corpus-level networks from document-level
        GSWs;
  \item compare TF--IDF, BM25, dense, hybrid, and structure-aware retrieval;
  \item execute and validate a neural question-decomposition plan;
  \item implement \RICR with chain scoring and diversity-preserving pruning;
  \item analyze generalization from 2WikiMultiHopQA to MuSiQue; and
  \item report accuracy, retrieval quality, latency, evidence size, and
        failure modes reproducibly.
\end{enumerate}

\section{Fixed definitions and default settings}

\subsection{Graph views}

For each GSW, construct the \textbf{native directed multigraph}. Entity and
verb-phrase/event records are nodes. A grounded QA record is represented by
directed, labeled edges that retain its stable QA ID, question, answer entity,
document ID, and relation to its verb-phrase. Do not merge records merely
because their display strings match.

Also construct an \textbf{entity projection}. The supplied helper normalizes
entity surface strings by case-folding, removing punctuation, and collapsing
spaces. Two normalized entity names are adjacent when they answer QA records
attached to the same verb-phrase. Store repeated co-occurrence as edge weight.
This is a practical reconciliation rule, not a perfect entity linker. Count
and discuss at least one possible false merge or missed merge. All component,
clustering, and assortativity results must state whether they were computed on
the native graph, its undirected view, or the entity projection.

\subsection{Retrieval and \RICR defaults}

Unless a question explicitly requests an ablation, use:

\begin{center}
\begin{tabular}{@{}ll@{}}
\toprule
Random seed & 232\\
Dense similarity & inner product of L2-normalized vectors\\
Reciprocal Rank Fusion & $\operatorname{RRF}(d)=\sum_r 1/(60+r(d))$\\
Pre-rerank candidate pool & $M=60$ unique QA records\\
Candidates returned per hop & $k=15$\\
Beam width & $B=5$\\
Chain score & geometric mean of hop scores\\
Generation & deterministic; sampling disabled\\
\bottomrule
\end{tabular}
\end{center}

For a length-$t$ chain $C=(e_1,\ldots,e_t)$ with positive hop scores
$s_1,\ldots,s_t$, use
\begin{equation}
  \operatorname{score}(C)
  = \left(\prod_{\ell=1}^{t}\max(s_\ell,\epsilon)\right)^{1/t}
  = \exp\left(\frac{1}{t}\sum_{\ell=1}^{t}
    \log\max(s_\ell,\epsilon)\right),
  \qquad \epsilon=10^{-12}.
\end{equation}
The log-domain form is recommended. At every pruning step, sort by decreasing
chain score and use the stable QA-ID sequence as the deterministic tie-breaker.
Retain at most one chain per normalized \emph{current answer}.

\subsection{Metrics}

Use the provided normalization functions. Report:
\begin{description}
  \item[Retrieval:] Recall@$k$ for $k\in\{1,5,10,15\}$, reciprocal rank/MRR,
        supporting-document recall, and supporting-QA recall.
  \item[Chains:] complete-chain recovery (all required supporting hops occur in
        one surviving chain), average surviving chains, and average unique
        current answers.
  \item[Answers:] Exact Match (EM) and token F1, giving each question the
        maximum score over its accepted answer aliases.
  \item[Efficiency:] wall-clock latency per stage, peak GPU memory when a model
        is used, number of reranked candidates, number of returned QA pairs,
        and answer-model input tokens.
\end{description}
Aggregate by macro-average over questions. Include the number of evaluated
questions in every table. Never average already-rounded subgroup values.

\section{How to build the system}

Build and test the project in the order below. Each stage has a small,
inspectable output that becomes the input to the next stage; do not begin with
the complete end-to-end pipeline.

\subsection{Load records and preserve stable identifiers}

Use \code{CoursePackage} to load JSONL records and the supplied matrices.
Represent graph nodes and retrieval candidates with their stable
\code{entity\_uid} and \code{qa\_uid}; never use a list position as an
identifier. Keep document ID, node type, edge direction, role/state text,
question, answer, and source retrieval score attached to the record. Before
building an index, assert that every matrix row has exactly one ID in its
matching ID file and that all IDs are unique.

\subsection{Construct the two graph views}

For the native directed graph, namespace node keys by node type so that an
entity and a QA record cannot collide. Add an entity node for each entity
record and a QA node for each QA record. Add the directed verb edge from its
source entity to the QA node and the directed answer edge from the QA node to
its answer entity. Preserve the originating document ID on nodes and edges.

For the entity projection, first collect the set of normalized entity names
that occur in each document. For every unordered pair in that set, add one to
the pair's co-occurrence weight. Remove self-pairs. Thus an edge weight is the
number of documents in which the two normalized entities co-occur, not the
number of times that their strings appear. Test this construction on a
three-entity hand-written document before processing the supplied corpus.

\subsection{Give every retriever the same interface}

Each retriever should return ordered records of the form
\code{(qa\_uid, score, rank, source)}. This makes the following methods
directly comparable.

\begin{enumerate}[label=\arabic*.]
  \item Fit TF--IDF and BM25 only to the supplied QA question strings. Transform
        a query with the same tokenizer and return the highest-scoring QA IDs.
  \item For dense retrieval, L2-normalize the query vector and use inner
        product against the supplied normalized QA vectors.
  \item For entity expansion, retrieve entities first and gather the QA IDs
        adjacent to those entities in the native graph.
  \item For RRF, assign each candidate its best rank in every source and sum
        $1/(60+r)$. A candidate absent from a source contributes zero.
  \item For dual retrieval, take the union of direct QA candidates and
        entity-expanded QA candidates, deduplicate by \code{qa\_uid}, truncate
        to the fixed $M=60$ pool, and only then apply the reranker.
\end{enumerate}

Write a toy corpus with one obviously relevant QA record and verify the rank
returned by every backend. This catches ID-order and score-direction errors
before they affect the full experiment.

\subsection{Parse the decomposition into an executable dependency graph}

Parse every generated line into a template ID and text. A placeholder such as
\code{<ENTITY\_Q1>} creates a dependency on the answer produced by Q1. Reject
duplicate template IDs, references to missing or future steps, and unresolved
placeholders. A template that calls for retrieval creates a retrieval node;
comparison, intersection, or other deterministic operations create operation
nodes. Templates with no dependency on one another form parallel sequences.
Topologically sort the graph and save both the raw model text and parsed
structure so parsing failures can be inspected without rerunning the model.

\subsection{Implement \RICR with a toy retriever first}

A chain contains an immutable ordered tuple of evidence records, the current
answer, the instantiated sub-question at each hop, and the log scores seen so
far. Implement the linear search in this order:

\begin{lstlisting}[language=Python]
beams = retrieve the first instantiated sub-question
beams = keep the best B distinct normalized answers
for each remaining template:
    expansions = []
    for chain in beams:
        query = substitute chain.current_answer into the template
        for candidate in retrieve(query, k):
            expansions.append(a new chain; do not mutate chain)
    score every expansion by its log-domain geometric mean
    beams = globally keep the best B distinct normalized answers
return beams and the complete trace
\end{lstlisting}

The pruning input contains as many as $kB$ expansions. Sort it once by
decreasing chain score, then by the tuple of stable QA IDs. Scan that order and
keep the first chain for each normalized current answer until $B$ remain. Do
not prune independently inside each parent beam. When parallel sequences have
finished, merge their evidence by stable QA ID and retain the provenance from
the highest-scoring occurrence.

First run this logic with a dictionary-backed toy retriever whose outputs you
control. After the two-hop, duplicate-answer, tie, empty-result, and $B=1$
cases pass, replace the toy retriever with the real retrieval interface. Run
\code{pytest -q tests}; the supplied \RICR tests are initially skipped while
the two functions contain \code{NotImplementedError} and become active
automatically after implementation.

\section{General grading and conduct}

\begin{itemize}
  \item A table or plot without axis labels, units, evaluated-question count,
        or a caption receives at most half credit for that item.
  \item Results that cannot be reproduced from the submitted code receive no
        implementation credit, even if the reported values are plausible.
  \item Clearly label any deviation from the required settings. An additional
        experiment does not replace a required one.
  \item You may use standard libraries for graph storage, TF--IDF, BM25, FAISS,
        plotting, and model loading. You may not import an implementation of
        \RICR or copy an answer key.
  \item Follow the course collaboration and academic-integrity policy. Cite
        all external code, prompts, and written sources.
  \item The course late-submission policy applies. If a released artifact is
        corrupted or a Colab dependency becomes unavailable, post a minimal
        reproducer to the course forum before the deadline.
\end{itemize}
